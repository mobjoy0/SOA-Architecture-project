# Student Service API Documentation

**Base URL:** `http://localhost:5049`

**Authentication:** All endpoints require JWT authentication with `ADMIN` role

---

## Authentication

All requests must include a valid JWT token in the Authorization header:

```
Authorization: Bearer <JWT_TOKEN>
```

**Required Role:** `ADMIN`

---

## Endpoints

### 1. Get All Students

**Endpoint:** `GET /students`

**Headers:**
```
Authorization: Bearer <JWT_TOKEN>
```

**Request Body:** None

**Example (cURL):**
```bash
curl -X GET http://localhost:5049/students \
  -H "Authorization: Bearer eyJhbGc..."
```

**Success Response (200):**
```json
[
  {
    "id": 1,
    "fullname": "John Doe",
    "email": "john.doe@example.com",
    "age": 20,
    "role": "ETUDIANT",
    "major": "Computer Science",
    "level": 3
  },
  {
    "id": 2,
    "fullname": "Jane Smith",
    "email": "jane.smith@example.com",
    "age": 22,
    "role": "ETUDIANT",
    "major": "Mathematics",
    "level": 4
  }
]
```

### 3. Create Student

**Endpoint:** `POST /students`

**Headers:**
```
Authorization: Bearer <JWT_TOKEN>
Content-Type: application/json
```

**Request Body:**
```json
{
  "fullname": "John Doe",
  "email": "john.doe@example.com",
  "age": 20,
  "major": "Computer Science",
  "level": 3
}
```

**Request Body Fields:**
- `fullname` (string, required) - Student's full name
- `email` (string, required) - Student's email address
- `age` (number, required) - Student's age
- `major` (string, required) - Student's major
- `level` (number, required) - Student's academic level

**Example (cURL):**
```bash
curl -X POST http://localhost:5049/students \
  -H "Authorization: Bearer eyJhbGc..." \
  -H "Content-Type: application/json" \
  -d '{
    "fullname": "John Doe",
    "email": "john.doe@example.com",
    "age": 20,
    "major": "Computer Science",
    "level": 3
  }'
```

**Success Response (201):**
```json
{
  "id": 1,
  "fullname": "John Doe",
  "email": "john.doe@example.com",
  "age": 20,
  "role": "ETUDIANT",
  "password": "generatedPassword123"
}
```

**Notes:**
- The password is automatically generated by the authentication service
- The student is created in both the auth service and local database
- Returns the generated password (store securely - won't be returned again)

---

### 4. Update Student

**Endpoint:** `PUT /students/:id`

**Headers:**
```
Authorization: Bearer <JWT_TOKEN>
Content-Type: application/json
```

**URL Parameters:**
- `id` (number) - Student ID

**Request Body:**
```json
{
  "fullname": "John Updated",
  "email": "john.updated@example.com",
  "age": 21
}
```

**Request Body Fields (All Optional):**
- `fullname` (string) - Student's full name
- `email` (string) - Student's email address
- `age` (number) - Student's age

**Notes:**
- Only provide fields you want to update
- If `email` or `fullname` is updated, auth service is also updated
- `major` and `level` cannot be updated via this endpoint

**Example (cURL):**
```bash
curl -X PUT http://localhost:5049/students/1 \
  -H "Authorization: Bearer eyJhbGc..." \
  -H "Content-Type: application/json" \
  -d '{
    "fullname": "John Updated",
    "email": "john.updated@example.com"
  }'
```

**Success Response (200):**
```json
{
  "id": 1,
  "fullname": "John Updated",
  "email": "john.updated@example.com",
  "age": 21,
  "role": "ETUDIANT",
  "major": "Computer Science",
  "level": 3
}
```

---

### 5. Delete Student

**Endpoint:** `DELETE /students/:id`

**Headers:**
```
Authorization: Bearer <JWT_TOKEN>
```

**URL Parameters:**
- `id` (number) - Student ID

**Request Body:** None

**Example (cURL):**
```bash
curl -X DELETE http://localhost:5049/students/1 \
  -H "Authorization: Bearer eyJhbGc..."
```

**Success Response (200):**
```json
{
  "message": "Student deleted successfully"
}
```

**Notes:**
- Deletes student from both auth service and local database
- This operation cannot be undone

## Authentication & Authorization

- All endpoints require a valid JWT token
- Token must be included in the `Authorization` header as `Bearer <token>`
- Only users with `ADMIN` role can access these endpoints
- Tokens are validated through the auth middleware

---

## Notes

- The service integrates with an external authentication API
- Student passwords are auto-generated during creation
- Student role is automatically set to `ETUDIANT`
- The service maintains data consistency between local DB and auth service
